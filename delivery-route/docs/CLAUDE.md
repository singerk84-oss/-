# CLAUDE.md — 배송 경로·운행일지 시스템

이관 문서("클로드 코드 이관 문서 — 배송 경로·운행일지 시스템")의 요약본이다. 모든 설명·주석·커밋 메시지는 한국어로 쓴다.

## 개요
- 자체 화물차(1톤·5톤·10톤) 일일 배송 자동화: 차량 배정·회차 산정 → 회차별 최적 경로 → 기사용 웹앱 → 운행일지 자동 기록.
- 출발·복귀지는 회사 고정, 하루 배송지 10곳 미만.
- 스택: Google 스프레드시트 + Apps Script(V8, clasp), HtmlService 웹앱, 카카오 로컬 API(좌표), TMAP 화물차 경로안내(구간 거리·시간).
- 화물차 높이·중량 제한 반영을 위해 경로는 기본 TMAP 화물차 API(차량 제원별 행렬). 카카오 길찾기는 승용차 기준이라 선택 옵션.

## 시트
- 기존: 설정, 거래처, 차량, 오늘배송, 운행일지, 일일마감(헤더는 config.gs HEADERS와 같아야 함)
- 자동 생성: 회차(회차별 예정 시각·링크·상태), 구간캐시, 오류로그

## 핵심 규칙
- 후보 차량: 화물최대길이 ≤ 적재함길이, 화물중량 ≤ 최대적재중량, 회사↔거래처 경로가 그 차량 제원으로 존재.
- 배차는 차량별 시간 행렬(timeByVehicle)을 쓴다.
- 목적함수: 초과시간×10000 + 전체 작업시간 합 + 0.1×최종 복귀시각.
- 시간 = 회차별 상차시간 + 이동시간 + 거래처 체류시간. 운행종료 초과 시 "차량 추가 필요" 경고.
- 수동지정 체크 + 배정차량ID + 회차 → 고정. 차량만 적으면 그 차량 안에서 회차 자동 배정.
- 운행일지는 배차 계산 때 회차별(배송지 순서 + '회사 복귀') 행을 미리 만든다. 운행이 시작된 날은 재계산을 막는다.
- 일일마감: 전일(가장 최근 이전 일자) 계기판과의 차이 = 실주행, API 합산은 출발 기록된 구간만.

## 시험
`npm test` — 경로 최적화(전수 탐색 대조), 배차 규칙, Apps Script 서비스를 흉내 낸 통합 시험(예시 데이터 → 회차 6개·링크 6개 → 웹앱 → 마감).

- TMAP·카카오 키 발급 후 실제 주소·경로로 검증(ROUTE_PROVIDER=estimate 해제).
- 2단계 알림톡: 대행사 결정 후 notify.gs `sendAlimtalk_` 구현.
- 향후: 카카오톡 주문 메시지 → 오늘배송 자동 입력.
